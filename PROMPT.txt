我要一个自助式数据查询工具，核心是让不懂 SQL 的分析师在浏览器里通过拖拽把想看的数据拼出来，后端负责把这套拖拽意图翻译成正确的 SQL 并执行返回结果。整个产品围绕"拖拽即生成查询"这一个能力做深做透，不要铺开成一整套企业报表平台。

先要有一层数据建模。用户导入若干张表（可以是随服务自带的一份样例业务库，比如订单、客户、商品、地区这类互相有外键关系的表），在建模界面里声明表与表之间的关联：指明两张表通过哪对字段连接，以及是一对一、一对多还是多对多的关系。用户还能在模型上定义三种派生对象：维度（可直接取用的分类字段，并支持声明层级，例如年到季度到月到日、或大区到省到市这种自上而下的钻取路径）；度量（在某个数值字段上施加求和、计数、去重计数、平均、最大、最小等聚合，并可带一个过滤条件）；计算字段（用类似电子表格的表达式在已有字段上做四则运算、条件判断、日期与字符串函数）。计算字段的表达式必须走一个白名单沙箱来解析，只允许预设的安全函数，禁止任何系统调用或访问文件；表达式在保存时就要校验语法并把错误位置指出来，而不是等到查询时才炸。

前端主体是一块查询构建面板：左侧列出模型里的维度、度量和计算字段，用户把它们拖到"行""列""数值""筛选"几个区域，页面据此实时向后端请求并把结果渲染成一张可排序的结果表（表格是主要呈现方式，不需要做一整套图表库）。筛选区支持下拉枚举、日期区间、数值区间几类条件。点击某个维度上的聚合值时，若该维度声明了层级，则向下钻取到更细一层重新查询。这里的交互是表单化的字段拖拽与区域投放，不是在画布上拉节点连线。

后端的可验证内核就是那台 SQL 翻译器：给定"哪些维度进了分组、哪些度量要聚合、模型里涉及哪些表、加了哪些筛选"，它要推导出需要连接的表并按声明的关联生成正确的 JOIN 链路、正确的 GROUP BY 与聚合表达式、把筛选翻成 WHERE、把下钻翻成在分组里追加更细层级。有几条规则要靠自动化测试守住并写明容差或期望：只涉及单表的查询不应产生任何 JOIN；跨表查询生成的连接路径要能覆盖所有被引用的表且不重复连接同一张表；一对多关联下对"多"侧度量求和的结果不应因连接被错误放大（避免重复计数）；同一组拖拽在字段顺序不变时应生成稳定一致的 SQL；下钻前后除分组粒度外的过滤与度量保持不变；用户所有输入的字面量都必须以参数化方式进入查询，禁止字符串拼接拼进 SQL，且只允许生成 SELECT 查询，任何写操作或结构变更语句都要被拒。请随产品带一份样例模型与几组预期查询，让人能核对拖拽到 SQL 的翻译结果。

请用 Python 3.12 加 FastAPI 实现后端与 SQL 生成内核，业务库用 postgres:16-alpine，前端用 React 实现拖拽查询面板，构建后由静态服务托管。请把前端拖拽面板、后端 HTTP 路由、数据建模（表/关联/维度/度量/层级）、表达式沙箱解析、SQL 生成内核、查询执行与结果整形分别拆成独立模块与文件，避免把 SQL 生成逻辑和建模、路由挤在一处。给出用容器编排把前端、后端和数据库一起启动、对外提供页面与接口的部署方式，并附自动化测试覆盖上面列出的翻译规则与参数化、只读限制。
